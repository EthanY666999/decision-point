| E11 | 树的实际额外叶子很少 | B2 PaTR 平均每题 5.53 片叶子（53,106 条轨迹 ÷ 150 步 ÷ 64 题），K=5 运行约 4.4 片。PaTR 的分数剪枝在 B2 第 26 步后只触发 2 次，第 76 步后为 0 |

**由 E8–E11 得到的设计结论：**
1. 排序分要保留过程价值 S（E8）。
2. 分叉点不能按固定频率放，而应放在模型犹豫、后果有分歧的节点上（E9、E10）。
3. 预算只需要每题 1–2 次分叉就能与现有的树对齐（E11）。
4. 关闭分数剪枝几乎没有影响（E11）。

**假设：** GRPO 的学习信号来自组内结果方差。好的树采样应当把有限的分叉预算花在「模型犹豫、而且不同选择会导致不同后果」的决策点上；同时，利用还是探索，应当取决于这一组当前的成功率。

## 2. 方法定义

### 2.1 总流程（每道训练题）
1. **第一阶段：初始采样。** 和 PaTR 一样从初始状态采 B0=4 条完整轨迹（V1 的采样器，T=1，最多 10 回合，单条 token 上限不变，保留重复动作剪枝 Θ=6）。唯一新增：每回合生成时让 vLLM 额外返回 `logprobs=20`（见 3.1）。
2. **记录节点。** 每条轨迹在第 t 回合、模型作答**之前**的那个时刻，记为一个节点 v=(j, t)。记录：
   - 状态 s_v；
   - 该回合作答在 token 序列中的起始下标 b_v；
   - 动作分布 π_v（来自第 1 步拿到的 logprob）。
3. **计算组成功率。** p̂ = 4 条初始轨迹中成功的比例。被剪枝或撞到回合上限都算失败。
4. **第二阶段：选分叉点。** 对所有候选节点计算排序分 U(v)（见 2.3），选出得分最高的 F 个**不同**节点。
5. **第三阶段：回溯续写。** 对每个选中的节点 v：
   - 复制父轨迹前 b_v 个 token（ids、mask、old_logprobs 原样复制，不做任何重分词）；
   - 重放动作 1..t−1，恢复环境，并断言恢复后的状态等于记录中的 s_v；
   - 从第 t 回合起重新采样，直到结束。剩余回合数为 10−t+1，剩余 token 预算等于原上限减去前缀已用的部分。
   - 每个分叉新增 1 片叶子，相当于在 v 处形成「原轨迹 + 新续写」两个孩子，和 PaTR 二叉扩展「+1 叶」的计数一致。
6. **训练。** 这道题共 4+F 条叶子轨迹，**只用结果奖励**做 GRPO 优势（组内减均值、除标准差，与 PaTR 现有实现完全相同），然后进入 V1 的更新流程。共享前缀在每片叶子中各算一次，与 PaTR 现有做法一致。

**默认参数：**
- 只回溯一轮（R=1），即所有分叉点都取自 4 条初始轨迹。R=2 是可选扩展，暂时不做。
- PaTR 的「分数剪枝」在 CERT 中**不适用**：没有同步分叉时刻，所有 CERT 臂统一关闭，在偏差表里注明。重复动作剪枝保留。

### 2.2 候选节点与去重
- 候选是每条初始轨迹的第 1 回合到最后一个作答回合，包括「走进洞的那一回合」，那正是决定性的决策点。
- **第 1 回合去重：** 4 条轨迹的第 1 回合节点前缀完全相同（同一个 prompt），只算一个候选。选中它，等于再采一条全新的独立轨迹。
- 更一般地，若两个节点的前缀 token 完全相同，就合并成一个候选。
- 同一个节点最多被选一次。

### 2.3 排序分（完整方法 CERT-UCT）
**U(v) = (1 − p̂) · S(v) + p̂ · H_cons(v)**

- **S(v)：** PaTR 的过程分，与现有 map_max 打分器相同，在状态 s_v 上计算：S = clip(1 − d_BFS(s_v)/(H+W−2), 0, 1)。
- **H_cons(v)：** 后果语义熵，见 2.4。
- **含义：**
  - p̂=0（全部失败）时只看 S，在最接近终点的地方回溯，争取一条成功；
  - p̂=1（全部成功）时只看 H，在模型犹豫、后果分歧大的地方回溯，争取一条失败，从而制造组内方差；
  - 中间情况按比例混合。
  - 没有需要调的超参数。这对应 UCT 中的「价值项 + 探索项」：PaTR 只有价值项，CERT 补上了探索项，并按组成功率自动调权。
- **平局：** 用固定种子随机打破，种子 = hash(base_seed, uid, step)，所有臂共用同一套种子。

### 2.4 后果语义熵 H_cons
在节点 v 处：
1. 从 π_v 读出 Up、Down、Left、Right 四个动作的概率，取法见 3.1。剩余概率记为「无效」。
2. 用确定性环境模型（非滑动 FrozenLake，地图信息与 PaTR 打分器所用相同）算出每个动作的后果类别：
   - 走进洞：类 `FAIL`（所有洞合并为一类）；
   - 到达终点：类 `GOAL`；
   - 越界撞墙：类 `STAY`；
   - 「无效」概率也归入 `STAY`，因为无效动作在环境里不移动。需要先核对 env 对无效动作的实际处理方式；
   - 其余情况：按到达的格子各成一类。
3. 按类别合并概率，计算 H_cons = −Σ_c P(c) log P(c) / log 5，取值在 [0, 1]。
4. **消融用的动作熵 H_act：** 不按后果合并，把 {Up, Down, Left, Right, 无效} 五类直接算熵，同样除以 log 5。

### 2.5 预算对齐
- F 为固定整数，所有 CERT 臂相同。
- **主预算：** F=2，即每题 6 片叶子，对齐 B2 PaTR 的 5.53 片。这个值由训练指标算出：round(5.53) − 4 = 2。
- **附加预算：** F=1，即每题 5 片叶子，对齐 K=5 树约 4.4 片以及 GRPO4 的 4 片。G1 里两个预算都跑；G2 和 G3 只用 F=2，除非 G1 显示 F=1 已经足够。这一点必须在看到任何验证结果之前定下来。
- 必须报告每步的生成 token、输入 token、执行动作数、耗时，并与 B2 的 PaTR/Random（K=2）以及原 K=5 运行比较。token 偏差超过 ±15% 要在报告中写明。

## 3. 技术实现细节

### 3.1 拿到动作分布（不改动采样结果）
- 在 V1 采样调用里，给 `SamplingParams` 加上 `logprobs=20`。**不改** temperature、top_p、seed 协议（`sha256(base_seed, task_uid, lineage, turn)`）、max_tokens。
- **定位动作词 token：** 对每回合生成的 token 序列，找到紧跟在开头反引号之后的第一个 token，也就是 ```` ``` ```` 之后的那个位置。用 tokenizer 写一个 CPU 测试，确认 "```Up```"、"```Down```"、"```Left```"、"```Right```" 的切分，以及每个动作的首 token id 集合。如果存在 " Down" 这种带空格的变体，也要收进集合。
- **组装分布：** 在该位置的 top-20 logprob 中，把属于各动作首 token 集合的概率加总，得到 P(a)；1 − ΣP(a) 记为「无效」。若该回合输出格式异常、找不到这个位置，则 π_v 全部记为「无效」，并单独计数。
- **说明：** 用首 token 概率近似整个动作的概率。FrozenLake 每回合的输出只有 3–4 个 token，这个近似很好；需要统计「首 token 是动作词、但最终解析失败」的比例并报告。
- **【11-02 修订：取代原来的「逐位一致验收」】采样调用完全不改，用独立探测获取分布。**
  - 原验收的结果：`logprobs=1`（生产设置）和 `logprobs=20` 两次采样，只有 90.2% 的轨迹一致；即使 token 完全一致的轨迹，old_logprob 也相差最多 0.115。这说明 vLLM 在异步批处理和 bf16 下，两次运行之间本来就不确定。原验收缺少「同一设置重复跑两次」这个对照，「逐位一致」的标准本身过严。这是任务书的问题，不是代码的问题。
  - **新做法：**
    1. 训练采样仍然用和 B2 完全相同的调用（`logprobs=1`，代码路径与 B2 逐字节一致），初始轨迹和续写都这样采；
    2. 4 条初始轨迹完成后，对每个候选节点做独立探测：输入 = 该节点的前缀 ids（截至 b_v）再接上开头的反引号 token（73594），设 `max_tokens=1`、`logprobs=20`、`temperature=1`，读出四个动作首 token 的概率，包括带空格的变体，见 `token_map`；
    3. 「无效」概率取 1 − P(以反引号开头)，由另一次 `max_tokens=1` 的探测在前缀上得到；
    4. 探测的输出一律不进入训练数据。前缀缓存打开，额外成本只有 prefill，需要单独记录探测的 token 数和耗时。
  - **新的验收：**
    1. 在 CERT 模式下，初始采样的 rollout 应当与「用 B2 的 collect 采样同一批题」在统计上一致：成功率、终局分布、平均回合数的差异，应落在两次 B2 collect 重复运行之间的差异范围内。同时报告这个重复对照（同一设置跑两次）的一致率，作为不确定性的基线。
    2. 探测得到的分布，与 rollout 中实际采样出的动作在统计上相符：被采样动作的平均探测概率与该动作的实际频率做校准对比。

### 3.2 回溯续写的正确性
- 新叶子的 `ids[:b_v]`、`mask[:b_v]`、`old_logprobs[:b_v]` 必须与父轨迹逐位相同（写断言）。之后新生成的 token 使用 V1 的 `apply_response`（原样保留采样 ID）。环境返回的文本只按 V1 原来的方式分词。
- 前缀的 old_logprobs 是在同一步、同一策略下采出来的，可以直接复用，**不重算**。
- **环境恢复：** 用同一个任务种子 reset，按父轨迹的动作重放 1..t−1，断言 state 等于记录值；不一致就跳过该节点，并记录原因。
- **采样种子：** 新续写的 lineage 命名为 `"{j}@{t}.{n}"`，种子按原协议用新的 lineage 计算。不同臂选中同一个节点时，续写结果必须完全相同（保证公平对比）。
- **不强制「换一个动作」：** 新续写在第 t 回合可能和父轨迹选同一个动作。不做拒绝采样，否则会破坏 old_logprob 的语义。记录这种情况的比例 `dup_first_action_rate`。这正是选高熵节点的意义所在：熵越高，重复越少。

### 3.4 CPU 单元测试（全部通过后才允许上 GPU）
1. 动作首 token 映射：四个动作和带空格变体都能识别，非动作 token 不会被误识别。
2. H_cons：
   - 墙角时多个动作合并为 STAY；
   - 两个相邻的洞合并为 FAIL；
   - 全部概率集中在一个动作时 H=0；
   - 均匀分布在 5 个类时 H=1；
   - 值始终在 [0, 1] 内。
3. 第 1 回合候选只出现一次；前缀相同的节点会被合并。
4. 回溯前缀的 ids、mask、logprobs 逐位一致；环境重放得到的状态一致；剩余回合数和 token 预算正确。
5. 每题叶子数 = 4+F（候选节点不足 F 个时少于 4+F，要记录）；全部叶子都进入同一个优势组；探测数据不会混进训练。
6. 五种选择器在同一份合成数据上给出预期的选点；平局按种子随机打破，并且可复现。
7. p̂ 的边界：p̂=0 时排序等价于按 S 排；p̂=1 时等价于按 H_cons 排。

## 4. 实验阶梯：先复用已有实验，再逐层训练

### G0：离线诊断（只用 CPU，不占 GPU，现在就可以做）

### G1：只采样验证（GPU，不训练；须在 B2 两臂都完成之后、拿到 GPU 锁后进行）
**复用 B1 的完全相同设置：**

- 题目：3 批 × 64 道训练题，B1 的种子 `SeedSequence([42, batch+1, 1701])`。

报告：
- 有信号题组数，与同一批题在 B1 中 K=2 和 K=5、PaTR 和 Random 的结果直接对比；
- **救回率（核心机制指标）：** 在 4 条初始轨迹结果相同（全对或全错）的题中，被 F 次分叉变成「有对有错」的比例。全对和全错分开报告；
- 新叶子的成功率、`dup_first_action_rate`、被选节点的回合分布、被选与未选节点的 H 分布；

**通过标准（事先固定，以 F=2 判定）：**
- CERT-UCT 的有信号题组数**严格多于** CERT-Uniform，且两个模型合并、按题 UID 聚类 bootstrap 的 95% 下界 > 0；
- **并且**不少于同批题 B1 K=2 中 PaTR 和 Random 的较大值；
- **并且** token 不超过 B1 K=2 的 115%。

另外，对 SFT→GRPO400 模型单独报告救回率。这个模型的策略已经很确定，最能检验「在确定的状态上分叉等于浪费」这一点。

不通过：停下来报告，不进入训练。同时报告 H_cons 和 H_act 两臂的结果，用于机制分析，但它们不参与关卡判断。

### G2：短训练 150 步（GPU）
- 从原始 SFT 独立初始化，seed42，配置除 CERT 相关键外与 B2 完全一致，每 25 步做一次固定验证。

- **通过标准（事先固定）：**
  - CERT-UCT 在第 100、125、150 步的验证成功率**都严格高于** CERT-Uniform，**并且都不低于** B2 PaTR K=2 在相同步数的值；

- 额外报告采样惊奇度曲线，检验 CERT 是否比 K=2 树塌得慢（参见 E9）。

### G4：机制消融（G3 有结论后进行，可先只用 seed42）
- CERT-S：只用过程分，检验「只利用」在 CERT 框架下的效果；
- CERT-H_act：动作熵；
- CERT-H_cons：后果熵，不做自适应混合。

这几组分别回答：
1. 自适应混合有没有用；
2. 后果聚类是否优于动作熵；
3. 回溯机制本身（CERT-Uniform）与固定 K 相比有没有用。

## 5. 事先写好的可证伪预测（写进报告，跑完后逐条对照）
1. 无 SFT 时，CERT-UCT 和 PaTR 的差距小于 SFT 时（p̂ 低时 CERT 接近只利用）。
2. SFT 设置下，CERT-UCT > CERT-Uniform，且不低于 Tree-Random。
3. CERT 的分叉点集中在第 1–3 回合以及洞边、墙边的状态；CERT-UCT 的 `dup_first_action_rate` 低于 CERT-Uniform。
4. 收益主要来自最短路 ≥ 4 的题和需要绕路的题；最短路 ≤ 3 的题已经饱和，不会有区别。
5. 训练后期（策略已经很确定时），CERT 有信号题组比例的下降比固定 K 慢；采样惊奇度的下降也慢于 K=2 树。
6. 救回率：CERT-UCT 高于 CERT-Uniform，在 SFT→GRPO400 这类已经很确定的策略上差距最大。

## 6. 执行规则（与之前一致）
1. GPU 一次只跑一个任务，使用同一把 `supervisor.lock`。CERT 的 GPU 任务只能按第 0 节的排程插在 B3 两臂之间；任何一臂运行期间，CERT 只能做 CPU 工作。
2. 新目录、新配置。冻结源码保持字节一致，并记录哈希和配置差异。
3. 每一层都有关卡，不通过就停止，把结果作为结论报告。
4. 只用训练集统计和固定验证集做选择；测试集只用于最终报告。
5. 一次只改一个因素，并报告真实的计算成本。
6. 租期由用户每天续，**每次启动长任务前确认平台显示的到期时间**。到期前 3 小时停止启动新训练，并做备份。
7. 磁盘不够时，先把已完成、已校验的产物移到 `/data`，不删除证据。
8. 每 20 分钟按原格式汇报。CERT 训练额外汇报：有信号题组比例、p̂ 分布、分叉回合直方图、`dup_first_action_rate`、每步 token。

## 8. 相关工作（论文中需要区分）
| 工作 | 做法 | 我们的区别 |
|---|---|---|
| ROSE（arXiv 2601.05053，徐志伟老师等） | 数学单回合；在语义熵高的位置分叉；从根节点做 ε 探索；长度感知的分段优势 | 我们用于多回合智能体；语义类别由环境后果确定，可以精确计算；与过程价值按 UCT 方式结合，并按组成功率自适应 |
| PaTR（arXiv 2607.15610） | 固定 K，按过程分选分支并剪枝 | 我们动态选分叉点，补上探索项 |
| AT2PO（arXiv 2601.04767） | 回合级 token 熵加兄弟数惩罚；熵加权的节点价值 | 只有熵，没有过程价值；不按后果聚类 |
| EPIG-Tree（arXiv 2609.20004） | 在最能降低梯度方差的位置放分支，实验包含 Wordle | 目标是梯度估计误差；我们的目标是过程价值与后果不确定性的自适应组合 |
| IGRPO（arXiv 2607.06223） | 按信息增益概率性地扩展 | 需要真实答案的似然 |
| BranPO | 对失败轨迹回溯 | 我们不看对错，按后果不确定性选分叉点 |
