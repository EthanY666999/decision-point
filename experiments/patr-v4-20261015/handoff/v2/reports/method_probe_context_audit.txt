实验二 V2 短验证上下文只读审计

结论：在已完成的 GRPO、PaTR、Tree-Random 原始记录中，未发现应用层漏加环境观测、漏保留历史、重复使用每轮 seed、复制错误响应，或前向采样与训练 teacher-forcing token 上下文错位。不能把“每轮 token 数接近”当成缓存错误；同时，不能仅靠本次 CPU 审计宣称彻底排除了 vLLM 内部 KV 缓存/注意力问题。

范围与证据
- 六份 validation_0000/0001.jsonl，共 96 条轨迹、536 次模型请求、528 次实际环境动作；8 次生成长度终止，不执行动作。
- 从初始地图独立重放环境，用冻结提示词和 tokenizer 逐轮重建完整初始 prompt、原始采样 token 历史、最新环境 user 后缀。
- 536/536 请求的完整 prompt token 前缀、采样 IDs、logprobs 对齐、文本解码、seed 公式、state_before 全部一致；528/528 环境动作、state_after、观测、reward 全部一致。累计检查 571075 个 prompt token 位置（含历史重复计数）。
- 每条多轮轨迹的请求上下文长度严格增长；同一轨迹内每轮 prompt hash 和 seed 均不同。源码 enqueue 直接把 list(b.ids) 交给 backend.add_request，未重用旧 prompt。patr_core.py、protocol_v2.py、train.py、numerical.py 的当前哈希均匹配本轮冻结指纹。

为什么看起来一直同长
440 个相邻回答对中，429 对 token 数相同，但真正全文相同的仅 190 对。190 对同文回答的 seed 全部不同，其中 54 对采样 logprob 也不同；其余 136 对同文同 logprob 的向量全部为 0。
具体例子：GRPO 初始验证第 1 行、首题、lineage 0，十轮都是 89 tokens；前三轮回答内的地图却明确把 P 从状态 5 改到 6，再改到 7。请求长度依次为 281、483、685、908、1131、1354、1577、1800、2023、2246 tokens。随后模型持续选择 Right，撞右边界，环境正确保持状态 7；新观测、合法撞墙提示和剩余步数继续进入 prompt，但模型重复旧回答。这支持“模型沿固定模板循环”，不支持“漏给新观测”。该模型还把 G 描述成 hole G，属于语义/决策错误，格式解析仍正常。

logprob 口径必须分开
- 训练 collect：temperature=1、top_p=1、top_k=-1；GRPO/PaTR/Tree/DAPO 使用完整模型词表，纠错 ARPO 只加 tokenizer vocabulary 掩码，actor/reference 的 head 概率归一化同步使用相同掩码。
- 验证 collect：temperature=0.7、top_p=0.8、top_k=20。核对运行环境 vLLM 0.9.2 sampler.py 第 279-295 行：先温度缩放和 top-p/top-k 过滤，再 softmax/log_softmax。因此验证记录中 0 logprob 是筛选后的采样分布；当只剩一个候选时，更换 seed 仍必然选相同 token。它不是原始模型概率，不能拿来直接算原始模型熵或跨框架训练 KL。
- 当前 train.main 与五方法 probe 都只把训练 collect 的 branches 传给 update/IS；evaluate 的 branches 保持局部，返回指标，不进入优化器。未发现把 .7/.8/20 验证 logprob 用进训练 IS 的路径。
- numerical_probe_initial 虽然选的是 validation 地图，但明确 evaluation=False，使用训练采样设置，无 optimizer update；其 512-token 诊断上限仅限数值探针，不能冒充完整效果验证。
- gradient_probe 使用 v1 PaTR 第 200 步的训练轨迹，并人为给两条轨迹交替 0/1 reward 以检查非零梯度。它是工程回归；旧策略 logprob 对初始 actor 的偏离不能当作新采样初始策略的 HF/vLLM 概率偏差。

RLen 不能仅看变大
初始 16 条验证轨迹累计 15325 tokens，RLen=957.8125。其中一条在第一轮无限重复“ _  _ ”，直到 10240-token 上限：这一条占总生成 token 的 66.82%。它未完成动作，属于退化，不是更充分的推理。PaTR/Tree 一步后的 16 条累计 26593 tokens，其中两条长度终止合计 20480 tokens，占 77.01%；RLen=1662.0625 不能表述为长度指标改善。JSON 保留了每条截断响应的文本片段和高频 token。

训练 teacher-forcing 额外抽查
抽查 11 条训练轨迹：GRPO 3 条（含最短 351-token、最长 9927-token 序列），PaTR 和 Tree 各 4 条（含共享前缀兄弟）。独立重建 IDs/masks 全部精确一致。把冻结 pack 函数仅在内存中将 device='cuda' 换成 CPU，检查 16045 个 assistant targets：标签就是 ids[:,1:] 在 mask[:,1:] 的位置，预测来自前一个 token；old_logprobs 的目标顺序、padding、attention 全一致。
共享前缀保留完整采样历史和相同 mask/logprob；这是树轨迹数据结构的正常复制，不是错误重采样。部分 pruned 轨迹末尾含未使用的新 user 提示，因为 apply_response 先补下一轮环境提示、随后才剪枝；这些 token 的 loss mask 为 0，既不新增 assistant target，也不改变前面的因果上下文。

当前短程配置
两配置均 seed=42、20 步、每批 16 题、minibatch 8 题、最多 10 轮、assistant 总预算 10240、上下文 32768、flat_group=8、initial_branches=4；训练与验证解码参数分别如上。legacy 保留未纠正的数值路径作为对照；behavior_variant 使用 bf16 forward projection、重算 frozen anchors 和 ARPO vocabulary 对齐。两者数值行为不同是显式实验设置，不是本次发现的上下文错位。

边界
没有新增 GPU 调用、修改源代码、修改配置或停止当前运行。没有读取或使用 reserved test/holdout 内容。保存的 branch IDs 加 enqueue 源码证明本实现构造并提交的上下文；未保存独立 vLLM request-level dump 或 KV 快照，故不能用本次 CPU 审计彻底排除内部缓存故障。需要进一步排除时，应在当前冻结验证结束后做同输入同 seed 的 cache-on/off 独立对照，而不是现在据均值临时改代码。
