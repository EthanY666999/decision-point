Question: Did the repairs after stopping the first formal run go too far and cause
the new policy collapse?

Finding
- The V2 "behavior_variant_v2" combined several algorithm/protocol changes.
  Its 20-step PaTR comparison did NOT establish a gain: fixed endpoint Success
  16.75 -> 18.75 percentage, paired 95% interval for difference [-2.25,+6.5]
  points; Pass@4 26 -> 29, interval [-3,+10]. Initial evaluation was already
  different (legacy 4/14, variant 8.5/24 Success/Pass@4), so the full-run choice
  cannot be justified as an isolated RL improvement. Promoting the combined
  variant to V3 formal training was too strong a conclusion from this evidence.
- V3 did NOT introduce a new training algorithm beyond V2 variant. The only
  train.py differences enable explicit 400-step formal mode, add disk guard,
  and save final test/model. patr_core.py, protocol_v2.py, and numerical.py are
  byte-identical between V2 and V3. V3 changes study scale from V2 20 steps,
  16 tasks/8-task minibatch to 400 steps, 64 tasks/32-task minibatch; same
  initial branches, learning rate, temperature, and algorithm variant. Thus
  the recent formal-mode code edit itself is not a demonstrated collapse cause.
- V1 was not a healthy diversity control: PaTR validation first responses at
  step 40 were Up 332/400 and Left 68/400; final step-400 validation was one
  identical incomplete ```Up`` first response in all 400 trajectories, parsed
  as invalid action 0, with overall invalid-action fraction 42.8%. V1 final
  test also had 400 identical incomplete Up first responses and 42.6% overall
  invalid actions. V1 Success/Pass@4 (validation 68.5/69, test 60/61) are
  actual environment scores but do not show healthy format or diversity.

Changes from V1 formal configuration to V3 formal configuration relevant to
PaTR:
  protocol/data: old seed-generated maps -> disjoint v2 maps; legacy agent
    prompt -> corrected_v2 prompt; validation/test populations changed.
  objective: trajectory normalization -> group_token normalization;
    invalid-action training penalty 0 -> 0.05; sampled KL estimator -> exact
    categorical KL; rollout anchor recomputed and importance ratio bounded.
  rollout: stable score ties -> randomized score ties; repeated-action pruning
    checked every turn; CPU/GPU numerical and cache-integrity fixes.
  engineering: microbatch 16/24000 tokens -> 2/6000; projected bf16 forward;
    per-task asynchronous scheduler, extensive trace and checkpoint checks.
  V1 and V3 outcomes cannot be paired across changed prompts, datasets,
    algorithm and temporal checkpoints.

Observed V2/V3 shared-split behavior:
  V2 variant initial validation 8.5 Success / 24 Pass@4 / 3.17 unique action
    paths per task; at 20 steps 18.75 / 29 / 3.29, with three first-response
    templates represented at endpoint.
  V3 initial validation 8.5 / 24 / 3.17; diagnostic step 24 16.25 / 17 / 1.90,
    and all 400 first responses exactly ```Right```.
  These observations demonstrate late behavior collapse in V3 after scaling
  the batch and passing the 20-step pilot horizon. They do not isolate whether
  normalization, penalty, prompt, KL formulation, batch size, or stochastic
  dynamics caused it.

Paper-protocol gap
- The PaTR paper states that process scores affect branch routing only, while
  standard GRPO uses terminal outcome rewards and averages each trajectory.
  The V2/V3 training invalid-action penalty and group-token normalization are
  named variants relative to that written objective. The paper appendix DOES
  specify LR 1e-6, clipping 0.28, KL coefficient 0.001, temperature 1.0,
  batch 64 and 400 steps, and K=5, all matching V3. Increasing KL would be
  a new stabilization ablation, not a correction to the published coefficient.
- The author's exact prompt, dataset and evaluation decoding may still differ;
  no author-exact claim is warranted.

Decision boundary
- Preserve V1, V2 and paused V3 data. Do not simply revert all repairs:
  source-integrity, action-format diagnostics, cache boundaries, tokenizer
  accounting and checkpoint safety address real defects; V1 also collapsed.
- For causal diagnosis, separate paper-faithful objective changes from
  stabilization experiments. Freeze one change at a time, run the same fixed
  validation and predefined short checkpoints, and inspect first-action
  distribution, Pass@4, path diversity, zero-variance groups and KL in addition
  to Success. Any changed training protocol starts from the base model with a
  new fingerprint; the paused step-24 checkpoint is not reused as a formal
  continuation under new settings. Full five-method rerun also needs storage
  and deadline feasibility, currently not available.
